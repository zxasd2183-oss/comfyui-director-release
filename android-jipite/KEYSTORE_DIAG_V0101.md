# 吉皮提 0.10.1：小米国行真机硬件密钥诊断修复

## 背景

在小米真机的 v0.10.0 中，即使安全锁屏和 `BIOMETRIC_STRONG` 预检通过，首次绑定也可能出现
“无法创建或验证硬件级审批密钥，已禁止绑定；请检查设备安全诊断”。

该提示是两个不同阶段的兜底报错，不能判断真实硬件是否满足要求，也不能断言配对成功。

## 0.10.1 的改进

- 不更改 Keystore 别名 `jipite-v06-approval`，也不删除、更换或重建已经存在的密钥；旧版升级不清除微软登录和 App 数据。
- 将密钥生成、读取 `KeyInfo`、安全等级、逐次认证、硬件强制认证与 `Signature.initSign` 的失败分成稳定的非敏感错误码。
- 在「审批 → 首次设备绑定 → 检查本机强生物识别和硬件密钥」中显示本机 **Android API、TEE/StrongBox/软件等级、身份认证开关、逐次认证标志、硬件强制认证标志、指纹变更是否令密钥失效**。
- 只有用户主动进入绑定时才可能创建密钥。查看诊断仍然严格只读，不调用 VPS、微软或 GPU。
- 绑定操作如果失败，会出现“未绑定 VPS · 本机安全检查”对话框，支持复制**仅包含安全属性和错误码**的诊断文字；不会包含配对码、令牌、公钥/私钥、证书、设备 ID。
- 小米真机登录成功后的提示不再错误地固定写“MuMu 只用于登录测试”。

## 如何验收

1. 在小米手机吉皮提「设置 → 应用更新 → 检查更新」升级 v0.10.1；保持同一签名的正常覆盖安装。
2. 进入「审批 → 首次设备绑定 → 检查本机强生物识别和硬件密钥」。
3. 如果此前的 v0.10.0 已创建密钥，诊断会显示它的硬件和认证属性。即使不通过也**不要删除密钥、清除数据或重置设备**。
4. 若仍有问题，复制**诊断文字**（不是配对码），用于继续定位具体 `KEYINFO_*`、`KEY_NOT_HARDWARE_BACKED`、`AUTH_NOT_HARDWARE_ENFORCED` 等错误码。
5. 本次是可观察性和设备兼容性定位更新，不宣称放宽过的认证要求或已在所有 Xiaomi HyperOS 设备上完成配对验证。

## 原有安全门槛仍保留

- `AndroidKeyStore` P-256，不可导出私钥。
- 每次签名都需要 `BIOMETRIC_STRONG`。
- 私钥必须受安全硬件保护，身份认证规则必须由安全硬件强制执行。
- 软件级密钥、未经证明的硬件状态、缺少逐次认证会**拒绝正式绑定和 GPU 审批**。
- VPS 侧仍采用微软身份认证 + 管理员一次性配对码；没有批准和签名不会执行 GPU 操作。

若发现小米系统返回的硬件强制认证结果与实际生物识别行为不一致，应先查证再决定是否需要额外的强验证/服务端远程证明，**不能直接删掉安全检查来“修复”**。
