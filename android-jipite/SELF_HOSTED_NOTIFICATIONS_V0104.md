# 吉皮提 V0.10.4：本地通知安全自检（无需制造 GPU 申请）

在 V0.10.3 已通过 Microsoft 身份、VPS 设备绑定、指纹签名、一次性挑战与防重放自检的基础上，本版增加**单独的 Android 系统通知测试**。

## 新增功能

- 在「设置 → 自建 VPS 通知（不接小米平台）」中，先开启「启用自己的 HTTPS 待审批提醒」，然后点击「发送本地测试通知（不操作 GPU）」。
- 通知内容明确写明「本地通知自检」，不会伪装成待审批 GPU 操作；点击只会打开吉皮提，不包含请求 ID，也不能触发任何批准。
- 不连接 VPS、不创建审批申请、不接触 Microsoft Token / 设备密钥 / 配对码 / GPU 电源接口，不更改真实提醒的去重记录。
- 分别检查 Android 13+ 通知权限、应用通知总开关及**实际待审批通知通道**是否被系统禁用。若权限不符，在设置页显示处理建议。
- 修复真实待审批提醒的一种漏报边界：系统应用通知或该通道被关闭时，不能把请求写入已发送去重摘要；重新允许通知后，新的有效轮询结果仍可提醒。

## 真机验收（安全、无 GPU 操作）

1. 通过现有应用内升级安装与原版相同签名证书的 V0.10.4；勿卸载或清除数据。
2. 打开「设置 → 自建 VPS 通知」，确认 HTTPS 提醒开关已开启。
3. 点击「发送本地测试通知（不操作 GPU）」并下拉通知栏，找到「吉皮提 · 本地通知自检」。
4. 点击通知，确认只是返回吉皮提，不产生待审批记录、不要求指纹、不执行 GPU 操作。
5. 若没有通知，检查吉皮提系统通知总开关、Android 13+ 通知权限以及「吉皮提 · GPU 待审批提醒」通知通道。

## 明确的验收边界

本地通知测试只验证 **Android 系统通知链路**。它不模拟 VPS 发出的真实待审批记录，不代表 HTTP 查询、MSAL 静默续期或后台 JobScheduler 已通过真机端到端验证。真实后台轮询由系统安排，HyperOS 省电策略仍可能推迟或停止后台执行；用户可始终到审批页手动刷新。

本版本无 Mi Push / FCM 依赖，无需小米开发者平台，GPU provider 继续保持原来的 read_only 权限。真正的 GPU 操作仍必须用户逐次确认、强生物识别和 VPS 验签。
