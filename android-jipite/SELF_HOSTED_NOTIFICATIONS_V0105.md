# 吉皮提 V0.10.5：Android 后台 Microsoft + VPS 只读查询自检

V0.10.4 本地系统通知测试通过后，此版本增加一次性后台任务，用于验证 Android JobScheduler 真正开始执行、Microsoft MSAL 能静默取得身份凭据、已绑定设备能通过 HTTPS 从 VPS 读取待审批状态。**没有虚构申请，不执行 GPU 开关机，不改变 VPS。**

## 新增内容

- 设置 → 自建 VPS 通知 → 「安排一次后台查询（不操作 GPU）」安排一个独立任务 ID，最早 10 秒后由 Android 调度；不是精确计时器，HyperOS/Doze 可能推迟它。
- 定期任务与诊断任务共用既有 JobService，严格单任务执行，避免重入覆盖正在运行的回调。二者都只调用已有 Microsoft 鉴权的 `/api/v1/mobile/pending`。
- 记录一次性检测与常规周期检测的最近时间和粗粒度结果（已排队、运行、通过、认证失败、VPS 查询失败、超时、中断）；不储存 Token、device_id、申请内容和原始服务端错误信息。
- 诊断完成后尝试发送单独的系统通知“后台 VPS 查询自检通过/未完成”，不会替代真正的待审批提醒，也不带可批准操作的请求 ID。
- 继续使用自建 VPS HTTPS、Android 原生通知与 JobScheduler，无 Mi Push / FCM、无第三方审批网页和额外 VPS API。

## 小米真机验收

1. 保持现有 App 数据与绑定，以原证书的正式签名 V0.10.5 覆盖安装。
2. 设置中开启“启用自己的 HTTPS 待审批提醒”；确保 Microsoft 登录已恢复、原有设备绑定有效。
3. 点击“安排一次后台查询（不操作 GPU）”，返回手机桌面并锁屏。
4. 如果系统执行并成功查询，收到“吉皮提 · 后台 VPS 查询自检通过”；点击打开设置页查看“通过：Microsoft 静默身份认证与 VPS 只读查询成功”。
5. 如果仍显示“已排队”，说明 Android/HyperOS 尚未安排运行，不要误报为网络失败。如果显示认证失败，回首页重新登录微软；查询失败检查 VPS 网络。
6. 只有等正式应用在小米真机实际出现成功记录，才能确认本机当时的后台任务端到端成功；这仍不意味着锁屏下**实时**或长期可靠地收到通知。

## 安全边界

两个后台任务没有电源执行能力，只能读真正的待审批记录；即使查询到真实申请，也只是发送提示，不能自动决定或批准。继续保持 VPS `read_only` 状态及每次强生物识别+签名验签要求。无需重装、重新配对、分享微软令牌或 VPS 私密配置。
