# 吉皮提 V0.6.1 · MuMu 模拟器离线测试

**此版本是无服务器调用的界面与交互演示**，不需要 Microsoft、Firebase、小米推送或 GPU 开机权限。

## 准备

1. 在 GitHub Actions 运行 **Build Jipite APK on GitHub**，选择 `preview`。也可使用推送自动构建的成功产物。
2. 下载 Artifacts 中的 `Jipite-V0.6-manual-UI-only` ZIP，解压得到 `app-manual-debug.apk`。
3. 在 Android 11 或更高版本的 MuMu 中拖入 APK 安装。
4. 打开应用，检查顶部是否出现 **【离线演示 / MuMu 测试】**，并且微软登录、绑定和真实刷新按钮不可用。

## 检查清单

- [ ] 点击“模拟开机申请”，看到 **启动 RTX 5090**、费用提示与以 `DEMO-` 开头的申请编号。
- [ ] 点击“模拟批准”，看到显式提醒：无真实指纹、无 VPS 请求、无 GPU 操作。
- [ ] 点击“取消”，申请应仍在页面上，审批按钮仍可用。
- [ ] 再次点击“模拟批准”并确认，看到“已模拟批准开机”，且申请自动清空。
- [ ] 点击“模拟关机申请”，看到“关闭 RTX 5090”和保存工作提醒。
- [ ] 点击“模拟拒绝”并确认，看到“已模拟拒绝关机”，且申请自动清空。
- [ ] 新建模拟申请后点击“清除模拟申请”，两个审批按钮不可用。
- [ ] 断开 MuMu 网络，再跑一遍上述流程；离线演示应仍可工作。
- [ ] 关闭并重新打开 App，没有任何模拟中的申请被误当成真实申请。

## 安全边界

- 手动 Debug 演示版通过 `BuildConfig.DEBUG && BuildConfig.FLAVOR == "manual"` 启用纯本地演示；在 `onCreate` 中提前退出，**不会初始化 MSAL、Push SDK 或走真实 API**。
- 模拟按钮不会发起生物识别 Keystore 签名，也不访问 `jipite.borealos.cn`。
- Release 正式审批版不启用模拟入口；需要另行配置微软 Client ID、稳定签名、VPS 后端和实际手机绑定。
- MuMu **不能代替**国行小米真机 Mi Push、后台保活、可靠强生物识别及真实 GPU 操作的最终验收。

## 如果出现错误

记录：模拟器安卓版本、APK 版本号、具体按钮、界面提示和异常截图。无需发送微软 Token、配对码、私钥或后端登录凭证。
