## 本批开发后端契约

- `GET /api/v1/workflow?project=<id>&kind=<kind>&episode=<id>`：仅 Microsoft owner，按项目/剧集返回版本记录、字段定义、真实引用图片和视频制作阻塞项。
- `POST /api/v1/workflow/save`：按 `expected_revision` 乐观锁写入草稿及不可变历史，限定明确业务字段。
- `POST /api/v1/workflow/review`：草稿→待审→人工批准/驳回；阻止跨项目图片、未批准场景/道具、无来源分镜及无前置计划白模。
- `GET /api/v1/workflow/reviews`：聚合项目真实待审工单、场景及角色分类资产；每条回到对应专有审核页面。
- `POST /api/v1/production/visual/upload`：复用既有 owner+CSRF+Origin 保护及源文件验证，支持 role/scene/prop/storyboard 私有候选图。图片最多 8MB，跨项目和综合图不能成为单体正式母版。
- 视频制作单仍**只能保存/提交/驳回**（不把计划批准当成生成成功）。真实 MP4 可由 Microsoft owner 分块回传，服务器必须验证 SHA-256、ffprobe 格式、画幅/时长/帧率及上游版本，然后作为独立 `video_take` 进入待审；仅人工审片可以批准实际产物。GPU 自动派单没有开启。
- 浏览器粗白模几何预览是支持相机和关键帧的编辑/规划工具，**不等同 Blender/Maya 的细白模模拟结果**。

2. GitHub 主分支全部 CI 通过后，**才一次性在 VPS 执行** `git pull --ff-only && bash scripts/deploy-director-all-once.sh`；脚本先做测试、FFprobe 依赖检查，再调用现有 Hub/Studio 的独立备份回滚升级器。无需多次上线。
3. VPS 执行后实际验证 Studio 200、私有匿名 API 401、服务 active、Hub 原有工具数不变、微软会话保留、GPU 保持 Stopped，以及 EP01 原有 31 镜头/160 秒/7 原图未改变。
4. 在 UI 验证道具、镜头引用、分镜版本、白模、整集制作包、真实 MP4 分块回传/播放器/审核、任务与项目规格，检查回传失败续传、非法跨镜头访问和旧制作单失效。
5. **独立验收阶段：** 需要真的启动经审批的 GPU 并打通 ComfyUI/H3 作业，然后测试真实生图、局部重绘和视频回传；未做前不能标为端到端已完工。

## Studio 视频回传 V1 的明确边界

- `/api/v1/workflow/video-packages` 导出完整整集清单，包括缺少批准的镜头和来源 SHA-256；GPU 端 `prepare-studio-batch` 绝不跳过阻塞镜头。
- `/api/v1/video-results/{start,chunk,finish,review}` 仅 Microsoft owner + CSRF + Origin 可写；每片最大 250MB、单块不超过 786432 字节、断点 24h 续传。按原文件哈希和 FFprobe 元数据验收，原 MP4 私有目录按 take ID 不可变保存；播放支持私有 HTTP Range。
- `video_take` 是真实上传并核验的媒体记录，人工审核其产物；原 `video_plans` 仍是**制作单**，不允许伪造视频生成成功。原镜头/资产改版后旧片仍保留，但就绪总览标识过期且不得作为当前版本新批准。
- 完整的 **GPU 自动开机/视频作业提交/回调自动回传** 尚需审批、GPU 实测与专用安全通信；本批不擅自调用 GPU，也不声称 H3、自动剪辑和配音已跑通。


## 2026-11-06 继续开发：安全整集回传与 VPS 本地 CPU 初剪

- GPU 收集器 `export-studio-delivery` 离线核对全部镜头 MP4、原始文件摘要及对应的 Studio 制作单版本，再导出一整个带清单的私有目录。
- Microsoft owner 可在 Studio 一次选择该目录；客户端核对整集镜头和最新批准版本，并逐镜头分块续传，服务器再次独立验证文件 SHA-256 / ffprobe。失败后可续传，完整重复提交不会生成重复视频。
- 已批准且当前有效的视频才进入整集“画面初剪就绪”统计。来源过期、缺任意镜头、未审核、视频流不兼容均拒绝整集拼接。
- Studio 提供经 Microsoft 登录、CSRF 和明确 CPU 操作确认的本地初剪队列。FFmpeg 工作线程在 HTTP 连接之外执行，记录持久化作业/审计/失败与最多两次故障恢复；GPU 端不被唤醒。
- 完成的初剪为独立不可覆盖的 `studio_picture_cuts` 记录，当前来源 SHA-256 失效后不能批准；需人工检查整集播放器并单独批准。不代表配音、音乐、音效、混音或成片封版。
- `scripts/deploy-director-all-once.sh` 是未来一次性 VPS 部署入口；当前仅 GitHub 代码及隔离测试，不修改生产数据库、服务配置和 GPU 状态。
