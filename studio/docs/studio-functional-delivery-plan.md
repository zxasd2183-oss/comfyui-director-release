# Director Studio · 全功能实施与验收台账

适用项目：WaitingOffice《待回答事务所》，EP01 31 镜头/160 秒/Revision 2。
策略：**一个业务模块对应一个可独立访问的工作区**；按真实数据、可执行操作、审计与回归逐个验收。严禁以单纯 UI 截图/空页面/未接 API 代替“完成”。本台账跟踪代码提交与部署，**合并主分支不等于 VPS 已部署**。

## 验收口径

每项功能必须同时满足：
1. 真实可持久化的数据模型（含项目隔离、版本与来源），能够读写回显。
2. Studio 自身的独立功能页面及可操作控件，非页内长滚动锚点。
3. 相关资产能够被下游安全引用；未批准内容不能被伪装成正式素材。
4. Microsoft owner 身份、CSRF、Origin、审计链、安全字段限制均通过。
5. 后端单测及前端路由回归通过；原 EP01 31 镜头、160 秒、7 张原图不变。
6. VPS 实际部署核验：服务 active，页面 200，匿名私有 API 401，Hub 工具数量不减少、GPU 不启动（涉及 GPU 的功能另行审批）。

标记只用：已在线验收 / 代码待部署 / 开发中 / 待开发 / 阻塞。不要用概念图数字充当真实进度。

### 场景库第一阶段精确验收
- GET /api/v1/scenes?project=...：列出项目场景及跨剧集关联图片。
- POST /api/v1/scenes/create：真实新建室内/室外/过渡/抽象场景，含布局、光照、镜头和连续性规则。
- POST /api/v1/scenes/update：显式 expected_revision；保存不可变旧版快照。已批准的历史版保留。
- POST /api/v1/scenes/link：只引用相同项目已存在的 kind=scene 图片；不复制媒体，跨项目拒绝。
- Studio 页面可选择本项目剧集上传 PNG/JPG/WebP 参考图，使用既有经过审计的视觉上传 API，上传后关联候选。
- POST /api/v1/scenes/review：草稿→待审→批准/驳回；批准必须选择本场景独立图片，审核者、理由、哈希和视觉 ID 留痕。
- 通过 GitHub CI 全量回归后合并；仅代码就绪，待 VPS 执行安全安装并实测。
